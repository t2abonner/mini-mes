# Mini-MES: Система оперативного управления производственными процессами

Уменьшенная копия системы **MES-MF**, воспроизводящая целевой технологический стек, архитектурные паттерны и ключевые интеграционные механизмы реального проекта в сокращенном масштабе.  

Проект реализован в рамках монорепозитория и ориентирован на отработку навыков построения отказоустойчивых фронтенд-приложений (SPA) с поддержкой Real-time данных и полноценного Offline-режима для цеховых терминалов.

## Быстрый старт

Откройте терминал и выполните ровно четыре команды:

```bash
# 1. Клонировать репозиторий
git clone https://github.com/t2abonner/mini-mes.git
cd mini-mes

# 2. Установить зависимости для всех воркспейсов сразу
npm install

# 3. Запустить клиентское приложение
npm run dev:web

# 4. Открыть в браузере → http://localhost:5173
```

**Как понять, что всё получилось:**

- В терминале Vite появилось сообщение вида `➜ Local: http://localhost:5173`.
- В браузере открылась страница с текстом **`Mini-MES`** — это сейчас рендерит `apps/web/src/app/App.tsx`.

> **Примечание.** Полный запуск `npm run dev` (клиент + mock-API) станет доступен в **спринте 3**, когда в `apps/mock-api` появится скрипт `dev` (таски `MM-301`–`MM-309`). Сейчас `dev:web` — основная команда локального запуска.

## Структура монорепозитория

```
mini-mes/
├── apps/
│   ├── web/                  # Клиентское приложение: React 18 + Vite + TypeScript
│   └── mock-api/             # Сервер-имитатор (Node + Express + Socket.IO) — заполняется в спринте 3
├── packages/
│   ├── contracts/            # Общие типы домена: сущности, статусы (единственный источник правды для типов)
│   ├── validation/           # Zod-схемы валидации + проверка типов на совместимость с contracts
│   ├── ui/                   # UI-кит + Storybook — заполняется в спринте 2
│   ├── eslint-config/        # Общие конфигурации ESLint / Prettier / Stylelint
│   └── tsconfig/             # Базовые конфигурации TypeScript (base / node / react)
├── docs/                     # Проектная документация (документы 1–6)
├── .github/                  # Шаблон pull request
├── CONTRIBUTING.md           # Регламент веток, коммитов и pull request
├── .husky/                   # Git-хуки (lint-staged)
└── package.json              # Корень npm workspaces
```

**Правило зависимостей воркспейсов.** `apps/*` могут зависеть от любого пакета в `packages/*`, а пакеты `packages/*` зависят друг от друга только по явно объявленным связям в `package.json` (например, `validation` зависит от `contracts`). Прямых зависимостей между `apps/*` быть не должно. Более глубокая архитектура слоёв внутри `apps/web` (`pages → widgets → features → entities → shared`) описана в документе 6.

В корне лежат `eslint.config.mjs`, `stylelint.config.mjs`, `.prettierrc.mjs`, `lint-staged.config.mjs`, `.editorconfig`

## Скрипты npm

| Команда | Назначение | Статус |
| --- | --- | --- |
| `npm run dev:web` | Запуск dev-сервера Vite на `http://localhost:5173` | ✅ работает |
| `npm run dev:api` | Запуск mock-API (`apps/mock-api`) | ⚠️ сломан: в `mock-api` нет скрипта `dev` — появится в спринте 3 |
| `npm run dev` | Параллельный запуск клиента и mock-API (`npm run dev:api & npm run dev:web`) | ⚠️ частично: `dev:web` стартует, `dev:api` падает с `missing script: dev` |
| `npm run lint` | Комплексная проверка: ESLint + Stylelint + Prettier — check | ✅ работает |
| `npm run lint:js` | ESLint по всему дереву | ✅ работает |
| `npm run lint:css` | Stylelint (CSS‑модули) с `--allow-empty-input` | ✅ работает |
| `npm run lint:format` | `prettier --check .` | ✅ работает |
| `npm run format` | Автоформатирование всего проекта | ✅ работает |
| `npm run test` | Тесты во всех воркспейсах (`--if-present`) | ✅ работает (сейчас только `validation`) |
| `npm run storybook` | Storybook в `packages/ui` | ❌ не настроен — появится в спринте 2 |
| `prepare` | `husky` — вызывается автоматически после `npm install` | ✅ работает |

**Точечный запуск по воркспейсу** можно выполнять через флаг `-w`:

```bash
npm run test -w @mini-mes/validation
```

## Проверка качества кода

```bash
npm run lint      # ESLint + Stylelint + проверка форматирования Prettier
npm run format    # Автоформатирование (Prettier --write)
npm run test      # Запуск всех тестов проекта (сейчас покрывает схемы validation)
```

> При каждом коммите работает **lint-staged** через **Husky** (скрипт `prepare` включает хуки автоматически после `npm install`). Проверяются только изменённые в коммите файлы — никаких дополнительных действий не требуется.
